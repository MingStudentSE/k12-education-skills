# 🗺️ 安装指南与发布信息

## 🚀 推荐安装顺序

> ⚠️ 重要原则：不要一口气全装。先把核心五件套用起来，再按实际学科和成长需求加装。

如果在 Obsidian 中作为项目级 SKILL 使用，建议先在 vault 根目录放置 `AGENTS.md`，并采用 `100-Raw / 200-Wiki / 300-Output` 三层结构。模板见 [AGENTS.k12-learning-vault.template.md](AGENTS.k12-learning-vault.template.md)，分层说明见 [Obsidian 学习仓库架构](obsidian-vault-architecture.md)。

### Obsidian 仓库接入前置判断

不要默认把完整模板覆盖到目标仓库。让 AI 先阅读 [AI 用 Obsidian 仓库接入手册](AI-obsidian-integration-manual.md)，再判断目标仓库是否已有结构：

| 目标仓库状态 | 动作 |
|------|------|
| 没有结构 | 创建中文直白命名的推荐三层目录，复制完整 AGENTS 模板 |
| 已有结构 | 保留本地规则，整理现有目录用途，只追加 K12 路由和写入映射 |

这一步由 AI 执行即可，不需要用户手动跑脚本。


## 📅 分阶段成长路径

### 第 1-2 周：先把基础飞轮跑起来

- 安装：#1-5
- 验证标准：至少完成一次“错题记录 → 费曼验证 → 提醒复习 → 周末复盘”

### 第 3-6 周：建立方法论系统

- 安装：#6-9
- 验证标准：能把错题、笔记、费曼结果和单题掌握流程放进同一条学习链路里

### 第 7-10 周：把执行层补齐

- 安装：#10-13
- 验证标准：能看到自己的计划完成率、专注时段和中断原因

### 第 11 周起：按学科深挖

- 只选当前最需要的 1-2 个学科包
- 验证标准：某一门学科的弱项开始形成“记录 - 训练 - 再验证”的重复节奏

## 📁 单个 SKILL 打包校验

每个 SKILL 应按独立目录打包。安装某个 SKILL 时，平台不应依赖仓库根目录的共享 `references/` 文件。

### 必须随包携带

```text
SKILL.md
references/   # 本 SKILL 使用的参考材料、模板、状态机
schemas/      # 本 SKILL 使用的数据结构、示例和校验脚本
```

### 上架前检查

- `SKILL.md` 中的 `references:` 路径必须是本目录内相对路径，如 `references/learning-zone-principles.md`
- 不允许出现 `../../../references/...` 或其他跨出当前 SKILL 目录的运行时依赖
- 如果多个 SKILL 都需要同一方法论，应在各自 `references/` 中放置精简版本
- 根目录 `references/` 只能放原始 PDF、研究资料或项目级资料，不计入单个 SKILL 安装包
- 安装包内至少要能通过“打开 `SKILL.md` → 找到 `references/` 或 `schemas/` → 执行核心流程”的自检

## ✅ 一句话选择建议

- 学习系统还没跑起来：先装包①
- 已经会记录错题，但总复盘不起来：加包②
- 明知道该学，但总执行不下去：加包③
- 某一门学科持续掉链子：只加对应学科包
