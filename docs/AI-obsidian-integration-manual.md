# AI 用 Obsidian 仓库接入手册

本手册专门给 AI 看。用户会把 `k12-education-skills` 仓库克隆到本地，然后让 AI 帮他把这套 Skill 体系接入自己的 Obsidian 笔记仓库。

注意：Skill 本体和 Obsidian 目录是解耦的。不要修改 `skills/` 下的 Skill 来适配某个 vault；只在目标 vault 的本地规则、目录和入口中做接入。

Skill 应安装到目标项目的项目级 Skill 位置。具体位置由用户使用的 AI 平台决定，例如 `.codex/skills/`、`.claude/skills/` 或平台自带的 Skill 管理器。安装时以单个 Skill 目录为单位复制或导入，保留目录内的 `SKILL.md`、`references/`、`schemas/` 等配套文件，不要只复制 `SKILL.md`。

## 总原则

1. 先判断目标 Obsidian 仓库是否已有结构。
2. 没有结构时，帮用户建立一套最小可运行结构。
3. 已有结构时，不覆盖、不重建、不搬空；先理解现有结构，再给出整理建议。
4. 不把完整模板硬套到已有仓库。
5. 不自动开启长期档案、提醒或跨 Skill 共享；这些必须由用户明确授权。
6. 不一次性接入 33 个 Skill；先接最小闭环，再按痛点增加学科专项。

## 第一步：判断目标仓库状态

打开目标 Obsidian 仓库根目录，检查这些信号：

- 是否有 `AGENTS.md`
- 是否有 `100-Raw/`、`200-Wiki/`、`300-Output/` 或类似三层目录
- 是否有学科目录、错题目录、周报目录、总控台、索引页
- 是否已经有大量 Markdown 笔记
- 是否已经有本地 AI 使用规则

只需要按上述信号判断，不需要脚本。

## 情况 A：空仓库或没有结构

判断标准：

- 没有 `AGENTS.md`
- 没有清晰目录
- 笔记很少，或只是零散测试文件

处理方式：帮用户建立新结构。

推荐创建。目录名尽量使用中文，含义直白，不使用游戏化术语。默认只建三层，不额外定义附件资产层：

```text
100-Raw/
  每日学习记录/
  课堂笔记原文/
  错题原始材料/
  学习资料/
  提醒与回执/

200-Wiki/
  学习总控台.md
  学习画像/
  学科知识/
    语文/
    数学/
    英语/
    物理/
  错题整理/
  学习方法/
  模板与规则/
  索引/

300-Output/
  学习计划/
  周报月报/
  复习资料包/
  阶段报告/
  临时生成/
```

然后把本仓库的模板复制到目标 vault 根目录：

```text
docs/AGENTS.k12-learning-vault.template.md -> AGENTS.md
```

复制后要替用户做一次本地化检查：

- 学段、学科是否匹配
- 是否要删除不使用的学科，例如用户不学物理就不要强行启用物理专项
- 写入位置是否符合用户的 Obsidian 使用习惯
- 是否需要保留用户已有少量旧笔记的原路径
- 如果用户偏好英文目录，可在用户确认后再改；默认使用中文直白目录。
- 如果目标仓库没有任何学习证据，不要生成 `学习画像/学习者画像.md`；可以先创建 `200-Wiki/学习画像/README.md` 说明画像需要授权和证据。

推荐先启用核心闭环：

- `learning-dna`
- `correction-notebook`
- `feynman-learning`
- `weekly-review`

不要一开始就启用全部 33 个 Skill。

## 情况 B：已有笔记或已有结构

判断标准：

- 已经有 `AGENTS.md`
- 已经有目录体系
- 已经有学科知识库、错题库、周报、总控台、项目页或其他长期笔记
- 已经有大量 Markdown 笔记

处理方式：不要套模板，先整理现有结构。

AI 应该先输出一份简短判断：

```text
我判断这是一个已有结构的 Obsidian 仓库。
我不会覆盖现有 AGENTS.md，也不会移动大量旧笔记。
我会先整理现有目录的用途，再把 K12 Skill 的输出映射到已有位置。
```

接着做三件事。

如果已有笔记中存在日记、错题、周报、课堂笔记或考试复盘，且用户允许建立学习记忆，可以调用 `learning-dna` 或对应复盘 Skill 生成初始学习画像摘要。没有足够证据时，不生成用户画像，只记录“证据不足，暂不建档”。

### 1. 识别现有目录用途

把已有目录归为四类：

| 类型 | 判断方式 |
| --- | --- |
| 原始证据 | 日记、课堂原文、拍题、图片、PDF、导入资料 |
| 编译知识 | 学科知识点、方法、错因、索引、规则 |
| 输出成果 | 计划、周报、月报、报告、复习包、导出 |

不要因为目录名字和推荐结构不同就要求用户改名。

### 2. 建立 K12 Skill 到现有目录的映射

输出一张映射表，例如：

| K12 Skill 产物 | 目标仓库现有位置 |
| --- | --- |
| 原始题面、学生原答案 | 用户现有原始资料或错题采集目录 |
| 错题卡、错因模式 | 用户现有错题目录 |
| 学科概念、方法卡 | 用户现有学科知识目录 |
| 周报、月报、阶段报告 | 用户现有报告或输出目录 |
| 学习画像、长期偏好 | 用户现有画像、仪表盘或总控台位置 |

如果用户没有某类目录，只建议新增最少的目录，不要重建整套结构。

### 3. 补充 AGENTS.md，而不是覆盖

如果目标仓库已有 `AGENTS.md`，只追加一小段：

```md
## K12 Skill 接入规则

本仓库已接入 k12-education-skills。Skill 本体保持独立，Obsidian 写入位置以本仓库现有目录为准。

- 错题记录、错因分析：优先使用 `correction-notebook`
- 理科题拆解与迁移：优先使用 `science-solving-four-steps`
- 看懂但讲不清：优先使用 `feynman-learning`
- 周复盘：优先使用 `weekly-review`
- 多 Skill 联动、月报、系统健康检查：按需使用 `skill-coordinator`

写入规则：

- 原始材料不覆盖，保留在现有原始证据目录。
- 错题卡、概念卡、方法卡写入现有学科或错题目录。
- 计划、周报、报告、复习包写入现有输出目录。
- 长期画像、提醒和跨 Skill 共享必须先获得用户明确授权。
```

如果目标仓库没有 `AGENTS.md`，但已经有结构，可以新建一个很短的 `AGENTS.md`，只写当前仓库的目录规则和 K12 Skill 路由，不要复制完整模板。

## 已有结构时优先接入哪些 Skill

已有仓库通常先接这几个：

- `correction-notebook`
- `feynman-learning`
- `science-solving-four-steps`
- `weekly-review`
- `skill-coordinator`

学科专项只在痛点明确时再接。例如：

- 数学错题多：`math-problem-solving-coach`、`math-error-dna`
- 英语语法问题多：`english-grammar-coach`
- 语文作文和阅读问题多：`chinese-writing-coach`、`chinese-reading-decoder`

## 禁止事项

- 不覆盖已有 `AGENTS.md`
- 不把已有目录强行改成推荐目录名
- 不自动移动大量旧笔记
- 不创建第二套学科库、错题库或总控台
- 不把 AI 生成内容覆盖原始证据
- 不默认启用长期记忆、提醒或跨 Skill 共享
- 不为了“完整安装”一次性启用全部 Skill

## AI 最终应交付什么

如果是空仓库，交付：

1. 已创建的目录结构
2. 已放置的 `AGENTS.md`
3. 建议先启用的 Skill 列表
4. 用户下一步应该从哪里开始记录

如果是已有仓库，交付：

1. 对现有结构的简短判断
2. K12 Skill 到现有目录的映射表
3. 建议追加到 `AGENTS.md` 的规则片段
4. 建议先接入的最小 Skill 子集
5. 哪些内容暂时不要动
