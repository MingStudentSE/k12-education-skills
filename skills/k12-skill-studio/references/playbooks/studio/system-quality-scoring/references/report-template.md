# system-quality-scoring 人读报告强制模板 v1.1.0

本模板约束评分任务的人读报告。任何 `system-quality-scoring` 运行完成后，除机读 `scorecard.json` 外，必须按本模板写入一份 Markdown 报告。

## 强制原则

1. **不得只给聊天摘要**：必须写入报告文件。
2. **不得只给 JSON**：JSON scorecard 是机读产物，不能替代人读报告。
3. **不得省略免责声明**：只要存在 `dry_run`、同模型自评、非盲测、场景覆盖不足、独立裁判缺失，必须在“重要免责声明”写清。
4. **不得重复或截断章节**：报告中每个一级区块只出现一次，不得保留 `Thought for ...`、流式残片、重复表格或半截句子。
5. **证据不足必须标注**：没有 trace 证据时写 `N/A` 或“证据不足”，不得补编。

## 文件命名

- 默认运行目录：`logs/scoring/YYYY-MM-DD_<engine-or-run>/`
- 默认报告路径：`<runDir>/REPORT.md`
- 默认 scorecard 路径：`<runDir>/scorecard.json`
- 盲测裁判 scorecard 可写入：`<runDir>/judged/<judge-or-run>.json`
- 最终聚合可写入：`<runDir>/FINAL_aggregate.json`

`<engine-or-run>` 使用小写 kebab-case，可保留模型版本点号，例如 `2026-06-19_gpt5.5`、`2026-06-20_deepseek-v4-pro`、`2026-06-20_blindtest-v2.1`。所有评分运行产物必须留在同一个 `<runDir>`；不得写入 `pipeline/`。

## 评级规则

维度评级用于报告展示，不改变 rubric 原始分数：

| 均分区间 | 评级 |
|---:|---|
| `>= 9.0` | 🟢 极强 |
| `>= 8.0` 且 `< 9.0` | 🟢 强 |
| `>= 7.0` 且 `< 8.0` | 🟡 中 |
| `>= 6.0` 且 `< 7.0` | 🟠 弱 |
| `< 6.0` | 🔴 弱 |

条形图使用 10 格：`█` 表示已得分，`░` 表示未得分，按均分四舍五入到最近整数。

## dry_run 与自评免责声明模板

当 `evalMode=dry_run` 或 EUT 与裁判为同一模型时，必须使用以下句式，允许补充但不得删除核心含义：

```markdown
本评估为 dry_run 同模型自评——<模型名> 同时担任 EUT（生成 trace）和裁判（打分）。存在自我评分偏高风险。

不可直接与 live 双盲基准比较，原因：
- live 双盲基准使用交叉盲评，裁判不见被测引擎身份；
- 本评是单模型自裁或非盲测；
- 场景覆盖为 <n>/5，缺少 <Sx/Sy> 场景。

建议下一步：由独立模型对 trace 进行交叉盲评，并补齐缺失场景，获得可比较的分数。
```
