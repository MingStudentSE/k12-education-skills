## 2. 四层结构

- 角色层：限定它是谁、只负责什么、不负责什么。
- 规则层：写出稳定行为，至少覆盖追问、反馈、边界、迭代。
- 状态层：区分当前结果、Learning State 和 Automation state；长期记录必须先获授权。
- 输出层：固定格式、语气和每轮下一步。

### 2.1 接口字段三分法

- `persisted`：经授权后真实写入状态或档案的字段；必须存在于状态/档案 Schema，并具备长度、枚举、格式、高敏禁止项和迁移规则。
- `derived`：由已声明输入实时计算的视图；写明输入、算法/判断规则和失效条件，不重复落库，不允许下游把它当成已存事实。若进入独立 output Schema，须标为只读/非持久化。
- `report-only`：只服务本次人读报告的文字或建议；不进入状态/档案 Schema，不回写状态，不作为未来结论的证据。若为传输或格式校验进入独立 report Schema，也必须标明非持久化。若排序由已声明输入实时计算，它属于 `derived`，必须说明规则和失效条件。
- 检查接口说明、状态 Schema、输出 Schema、示例和报告模板：同一字段只能属于一类；若要从 `derived` 或 `report-only` 升级为 `persisted`，必须按新增持久化字段重新走授权、状态 Schema 和回归。

## 3. 学习科学必检

- 单目标与反多任务：每轮只推进一个学习动作。
- 主动回忆优先：学生先讲、先写或先预测。
- 错误反馈闭环：错误→修正→再犯预警→变式验证。
- 交错与分散练习：不要只做同类重复，安排易混与复测。
- 固定版式与图表：记录字段稳定，概念优先可视化。
- 学习区与熔断：太易加迁移，太难降支架。

## 4. 五步创建流程

1. 定义需求：从真实学习痛点出发，不先写漂亮提示词。
2. 设计四层：角色、规则、记忆、输出逐层落地。
3. 投喂资料：给关键材料、格式样例和反例，不上传无关隐私。
4. 测试迭代：用 happy path、信息不足、越界请求和失败案例测试。
5. 上线维护：用 3-5 次真实对话后再改一轮。

## 5. 七项健康指标

- 使用连续性：每周至少有 3 次授权上下文延续。
- 上下文关联：能连接上次错误和本次问题。
- 返回精准：能具体引用已投喂资料。
- 定期更新：资料库不过期，至少按月维护。
- 批判性校对：用户能纠正不合适追问。
- 语气熟悉感：回应不像每次初见。
- 学习科学命中：稳定命中主动回忆、错误反馈、分散复习、交错练习、学习区中的 2-3 项。

## 6. 常见误区修复

| 误区 | 修复 |
|---|---|
| 角色太宽 | 明确“只负责/不负责” |
| 规则太少 | 补到至少 4-6 条可执行规则 |
| 记忆太模糊 | 改成具体字段列表 |
| 不迭代 | 强制“用 5 次→改一轮” |
| 只会讲解 | 加入学生先讲/先做/先预测 |
| 把派生指标或报告句写成档案字段 | 先做 `persisted / derived / report-only` 分类，只有真实状态进入状态/档案 Schema；其余只能在独立只读输出契约中出现 |
