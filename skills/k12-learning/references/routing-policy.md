# K12 Learning 内部路由规则

## 原则

1. 明确的“第一次使用”信号优先建立最短 onboarding；已有材料不绕开 onboarding，而是直接成为快速测评与第一项真实任务的证据。非首次请求仍以当前明确目标和强材料信号优先。
2. 一个主 playbook 对当前结果负责；辅助 playbook 最多两个，且必须直接改善同一结果。
3. 路由只用当前消息。历史证据在选择完成并通过授权门后按需读取。
4. 学科是稳定的一级路由维度，方法是 module 内部 mode。不要仅因学科不同就新增公开 Product Module。
5. 核心素养是主 playbook 选定后的执行证据镜头，不是一级路由、辅助 playbook 或新的 capability。

## 高频冲突

| 冲突 | 选择 |
|---|---|
| 系统介绍 vs 首次启动 | 只问“你能做什么/平时怎么说”走 system-guide；明确“第一次使用”走快速测评 + 初版学习 DNA，能力介绍只能作为简短补充 |
| 首次启动 vs 当前题 | 首次使用以快速测评为主，把当前题直接作为测评材料，并在生成初版 DNA 后立即继续这道题；不另起长问卷 |
| 普通当前题 vs intake | 非首次且有具体材料直接处理；无明确任务才 intake |
| 当前解法 vs 反复错因 | 当前步骤走单题；有多次证据才走 error-dna |
| 错题首次处理 vs error-dna | 首次走 correction；长期模式走学科 error-dna |
| 概念解释 vs 费曼 | “请解释”走概念；“我来讲”走费曼 |
| 普通单题 vs 四步法 | 普通卡点走学科单题；“学透/遮住不会/变式”叠加四步法 |
| 计划 vs 专注 | 未形成安排走计划；计划已有但执行失败走专注 |
| 周复盘 vs 360 | 单周轻复盘走 weekly；多周证据评级走 360 |
| 跨学科项目 vs 学习编排 | 主题研究走侦探；同一学习结果需要多方法时内部组合 |
| 笔记内容 vs Wiki 结构 | 内容组织走康奈尔；目录、索引、入库走 llm-wiki |
| 文本提醒计划 vs 真实提醒 | 文本计划留在本 module；真实调度走 automation |
| 核心素养 vs 学科任务 | 仍由当前学科 playbook 负责结果；义务教育且需要课标对齐时，按 `curriculum-evidence-policy.md` 选一个证据模型 |
| 2022 义务教育 vs 高中 | 高中不套用 2022 模型；未建立对应高中事实库时，只给通用证据链并明确版本边界 |

## 最小澄清

只有两个候选会产生不同下一步时，问一个问题：

- “你现在想解决这道题，还是分析为什么同类题反复错？”
- “你想让我解释，还是由你讲一遍、我来检验？”
- “你需要安排任务，还是已有计划但执行不下去？”
- “你想整理这页内容，还是维护整个 Wiki 仓库？”

不会改变主 playbook 时直接执行，不追问年级、教材、画像和授权全套信息。首次启动也只补材料无法推断的年级与当前目标，不收齐字段再开始。

## 组合规则

- 组合由 `k12-learning` 主流程直接决定；playbook 不拥有独立路由权，也不定义彼此传消息的协议。
- 首次启动：`student-quick-assessment` 为主，`learning-dna` 形成会话内初版画像。若用户已提供具体材料，第二个辅助位使用对应学科方法并立即处理材料；若没有材料且同时问“你能做什么/平时怎么说”，第二个辅助位使用 `system-guide` 做简短介绍。不要同时加载向导和学科方法而挤出真实任务。
- 学科单题 + 四步法：用于“学透、遮住不会、做变式”；用户明确要求自己复述并接受追问时，再追加费曼。
- 错题处理 + 学科 error-dna：仅在用户提供反复证据时。
- 学科概念 + 康奈尔：用户明确要形成自测笔记时。
- 计划 + 专注：先产出可执行计划，再解决执行阻力；不要并行给两套任务。
- 任何组合涉及历史、写入、提醒或跨 module 时，先走授权门。
- 课标证据镜头不计入“最多两个辅助 playbook”，但一次只加载当前学科的一份 profile、只选一个主素养；首次使用不得因此增加测评动作。
