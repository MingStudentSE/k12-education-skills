# 📊 每周学习复盘方法

> **一句话定位：** 把一周学习记录整理成有证据、有温度、有下一步的周报，而不是模糊地说“还行/不行”。

## 触发条件与不触发边界

**使用本方法：**
- 用户说“生成本周周报 / 这周学习复盘 / 总结一下这周 / 下周重点是什么”。
- 目标是周级轻量复盘：整理本周学习记录、计划完成、错题/费曼/提醒摘要，输出周报、成长证据、学习区判断和下周一件最重要的事。
- 允许处理“本月情况怎么样”的入口，但只汇总已授权的周报摘要；若用户要全景评级或系统审计，切换到 `learning-360-review`。

**不要使用本方法：**
- 明确要求“阶段学习体检 / 360 复盘 / A-B-C 评级 / 系统审计 / 最近两周学习系统运转得好吗 / 考前准备状态评级”：切换到 `learning-360-review`。
- 只要单题讲解、错题订正、费曼讲解、明天计划或专注力诊断：分别切换到相关学科方法、错题本、费曼、学习计划或时间专注方法。
- 证据只有感受且用户要求打分：不要冒充体检；先给本周补证据模板，若仍要评级则切换到 `learning-360-review` 并说明证据门槛。

**与 `learning-360-review` 的互相边界：** weekly-review 负责“周报/轻量周复盘/下周重点”，不输出 A/B/C 评级；learning-360-review 负责“阶段体检/多维证据审计/评级/系统修复”。同时命中时，若用户只要本周周报，weekly-review 优先；若出现“评级、360、体检、系统审计、阶段判断”等意图，weekly-review 先切换到 learning-360-review，并可提供本周摘要作为证据。

## 核心流程骨架

1. **确认范围**：确认日期范围通常为本周，并说明这不是阶段评级；若范围含多周且要评级，切换到 `learning-360-review`。
2. **收集最小输入**：请求本周学习记录、计划完成情况、错题/费曼/提醒摘要、情绪或专注异常；只取当前周所需字段。
3. **先回忆后汇总**：先让学生说本周最重要收获、卡点和一件想改进的事，再用数据校准，避免完全代替复盘。
4. **生成六模块周报**：按一句话总结、知识点地图、错题薄弱点、理解深度/成长证据、执行力、下周重点输出；细则见完整手册。
5. **做学习区检查**：判断本周任务落在熟悉区、学习区还是挫败区，并给下周调参动作；学习区标准见共用原则。
6. **输出双通道版本**：学生版强调自我理解和下一步；家庭分享版只给温和、可执行支持，不制造成绩焦虑。
7. **授权后沉淀**：如需写入学习 DNA、提醒或给 360 体检做证据，只传递最小摘要并先获得用户同意。

## 失败模式与红线

- 不臆造学生长期数据、完成率、错题次数、历史趋势或家庭情况；数据少时明确“结论仍在积累中”。
- 不把复盘做成空泛鸡汤；所有进步、问题和建议必须绑定具体事件、证据或可补充字段。
- 不只看完成率；必须检查主动回忆、错误反馈、交错练习、分散复习和学习区命中。
- 不一次给一堆下周建议；下周只聚焦一个最重要动作，并给验收方式。
- 不羞辱、不贴人格标签；高压或挫败时优先减载、修复系统和给家庭低压支持。
- 不默认向 `k12-automation` 提交提醒请求、写入档案或在内部组合中共享；未授权时只输出本轮结果。
- 不越权生成月度全景报告或 A/B/C 阶段评级；这类需求切换到 `learning-360-review`，其余组合由 `k12-learning` 主入口决定。
