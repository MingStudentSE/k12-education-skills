# 数学错误DNA操作手册

> 本文件承接原 `playbook.md` 的长流程、模板、内部组合边界与输出格式；主文件只保留触发路由和执行骨架。

# 🧬 数学错误 DNA

> **一句话定位：** 普通错题本告诉你"哪道题错了"——
> 数学错误DNA告诉你"你为什么总在同一个地方出错"，
> 然后用数据消灭那个模糊的"我数学不行"的感觉。

---

## 最小执行闭环

1. **判断触发**：确认本次任务是否属于数学错因模式、概念混淆或长期错误画像；如果不是，先指出更合适的方法，或仅做普通回答。
2. **收集最小输入**：只追问完成任务必需的信息：数学错题、学生步骤、错因自述和历史同类错误。信息不足时，先给可选模板让学生补充，不臆造长期数据。
3. **执行主流程**：按后续章节推进，优先用追问、验证、例子和小步反馈帮助学生自己完成关键思考；不要把可训练的步骤直接替学生做完。
4. **产出结果**：给出错因分类、概念混淆图、纠偏策略和复测计划，并明确“现在能做的下一步”。
5. **复盘与写入**：若需要沉淀到长期系统，先说明写入路径和理由；未获授权时只输出本轮结果，不更新档案、不调用 `k12-automation` 创建提醒、不跨 module 共享。

---

## 通用边界与降级策略

- **信息不足**：先请求最小补充信息；不要为了推进流程而编造学生水平、历史记录或学习数据。
- **任务不匹配**：说明当前方法不适合的原因，并建议更合适的方法或普通回答路径。
- **学生只要答案**：可以给必要帮助，但先提示“快速答案”和“真正掌握”是两种目标；若学生坚持，只回答当前问题，不强行进入完整训练。
- **长期记录**：只有在用户明确同意后，才更新档案、画像、提醒或跨 module 共享摘要。
- **跨 module 联动**：只传递当前任务需要的最小摘要，不默认展开完整历史。
- **难度失配**：太容易时增加解释、变式或迁移；太困难时拆成子问题、补前置知识或降一级练习。

## 一、核心使命

**传统错题处理的问题：**

```
出错 → 看答案 → 抄步骤 → 下次同类题，还是出错
               ↑
         处理的是"这道题的表面"
         没有处理"出错的根因"
```

**这个方法解决的问题：**

```
出错 → 分析根因 → 分类存档 → 发现规律 → 顽固弱项专项突破
                            ↑
                  从"这道题"上升到"这类错误"
                  从孤立事件变成可分析的数据
```

⚠️ **【架构定位——通用记录与数学深度诊断】**

`correction-notebook` 和本方法都是 `k12-learning` 的内部实现。前者提供通用错题记录视图，后者提供数学深度诊断视图；它们不彼此调用或传递中间消息。`k12-learning` 只在同一份当前结果中按需组合两种视图。

| 职责 | 归属 | 说明 |
|------|------|------|
| 当前错题与学生尝试 | `k12-learning` 主流程 | 唯一入口，原题证据只收集一次 |
| 拍题三信息法（信息收集） | 通用错题记录视图 | 提取题目、学生答案和卡点 |
| 基础四维分类（概/计/审/策） | 通用错题记录视图 | 作为同一结果的通用维度 |
| 表面信息存档 | 通用错题本 | 记录题目、答案、日期、来源、状态等表面字段 |
| **子类型精确定位（C01/B01 等）** | **数学深度诊断视图** | 结合通用维度与原题证据，完成深度子类型定位 |
| **跨维度关联分析** | **本方法** | 通用错题本不做跨维度分析 |
| **顽固弱项识别与专项突破** | **数学深度诊断视图** | 只在多次独立证据或复测支持时升级为模式 |
| **数学焦虑处理** | **当前主 playbook** | 用题目证据和最小任务替代模糊贴标 |
| **数学弱项月报** | **本方法** | 独立生成，通用错题本不重复生成数学月报 |
| 学期全景报告·数学章节 | 通用错题本（汇总层） | 本方法提供数据，通用错题本做跨科目汇总呈现 |
| 复测建议 | `k12-learning` | 只生成内容、建议时间和掌握判据；不代表已创建提醒，真实调度走 `k12-automation` seam |
| 真实提醒 | `k12-automation` | 通过独立 interface 展示渠道、频率和下次触发时间，并自行取得授权 |

**核心原则：通用层记表面，数学层记根因；不产生重复记录，不重复触发预警。**

## 二、四类错误分类体系

这是整个档案系统的核心——每一道错题都必须归入且只归入一类：

| 错误类型 | 定义 | 典型特征 | 根治方法 |
|---------|-----|---------|---------|
| 计算失误 | 解题思路正确，在运算过程中出现错误 | 换个题目做得出来；改了数字就出错 | 专项计算步骤训练；找到"哪一步操作"最容易出错 |
| 概念模糊 | 对某个定义、定理、公式的理解有偏差 | 不知道什么情况下该用；把相似概念混用 | 概念追问；用类比重建理解；见references/concept-confusion-map.md |
| 方法用错 | 知道相关知识点，但选错了解题策略 | 思路对但绕远路；题目变形后就不会了 | 题型识别训练；梳理"哪类题用哪类方法"的对应关系 |
| 读题失误 | 题意理解偏差，漏读或误读条件 | 看了三遍题目但漏了关键词；审题不完整 | 读题习惯训练；高亮关键词练习；见references/reading-habits.md |

```

```


### 触发记录的时机

```
经学生同意后可触发：
├── 数学解题教练方法完成错题分析后 → 建议记录
├── 学生说"已经明白了"且验证通过 → 可更新状态为"已攻克（待验证）"
└── 同类题做错第2次 → 可将两条记录关联，升级优先级

手动触发：
├── 学生说"帮我记录这道错题"
└── 学生发来错题图片说"存入档案"
```

## 四、顽固弱项追踪机制

### 触发标准

**同类错误（相同错误类型+相同知识点标签）出现3次时，可提示进入专项跟踪：**

```
🧬 档案提醒：
"我发现了一个规律——
 你在[知识点X]上的[错误类型]已经出现了3次：

 第1次：[日期] [题目概述]
 第2次：[日期] [题目概述]
 第3次：今天  [题目概述]

 这可能是一个'顽固弱项'。
 如果你愿意，我可以把它加入持续跟踪档案，后面专门帮你验证和突破。
 现在有10分钟吗？我们来处理它。"
```

### 顽固弱项专项突破流程

```
Step 1：根因确认
不复述之前的分析——直接出一道"纯净版"题
（只包含这一个知识点，排除其他干扰）：
"先做这道题，只需要30秒：[纯净版题目]"

Step 2：规则重建
如果纯净版做错：说明是真正的概念/方法问题
→ 在同一结果采用数学概念解释方法，重建这个知识点

如果纯净版做对：说明是干扰条件下识别问题
→ 出3道"加入干扰条件"的递进题

Step 3：验证锁定
"你刚才做对了——但我还不完全放心。
 明天我会再出一道同类型的题给你，
 连续两次做对，这个弱项才算真正攻克。"

Step 4：写入档案
在学生同意持续跟踪时，更新该条目状态为"突破中"
若学生同意真实调度，向 `k12-automation` 提交次日和 3 天后的验证题提醒请求
```

## 五、错误类型图谱

**触发：** 学生说"帮我分析我的数学错误规律"时生成；不默认按月生成

### 图谱生成逻辑

从档案中统计所有错题记录，生成以下结构的分析报告：

```
📊 数学错误类型图谱
统计时间范围：[本学期 / 本月 / 自定义]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
错误类型分布：

计算失误     ████████████ 38% (N次)
概念模糊     ████████     24% (N次)
读题失误     ███████      22% (N次)
方法用错     █████        16% (N次)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
AI诊断：

[计算失误占比>30%]
→ 计算失误比例偏高。
  深挖：这[N]次计算失误集中在[具体步骤]——
  其中[X]次发生在符号处理，[Y]次发生在分数运算。
  建议：专项针对[符号处理/分数运算]的流程训练，
  不是多做题，而是放慢速度做对每一步。

[概念模糊最集中的知识点]
→ 概念模糊主要集中在[知识点A]和[知识点B]。
  这两个知识点有一个共同点：[分析]。
  建议：先用概念解释器重建[知识点A]的理解，
  再做3道纯概念应用题确认。

[读题失误高频触发词]
→ 读题失误中，有[X]次都涉及"[关键词]"这类条件——
  这说明你对含有[关键词]的题型需要特别注意审题习惯。
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

顽固弱项清单：

🟡 [弱项2]（已出现N次，状态：突破中）
🟢 [弱项3]（已攻克，上次错误：[日期]）

近期进步：
✅ [弱项X] 连续2次做对，已标记为攻克
✅ 计算失误率本月比上月降低了[X]%
```

## 七、数学焦虑专项处理

### 识别数学焦虑的信号词

```
触发信号：
- "我数学太差了"
- "一考数学就脑子空白"
- "感觉怎么学都学不会"
- "明天考试，我完全没把握"
- "我就是没有数学天赋"
```

### 标准处理流程：数据替代情绪

```
Step 1：确认感受（1-2句，不展开）
"你现在很担心，我听到了。
 先别急，我来看一下你的档案说了什么。"

Step 2：调取精准数据（关键步骤）
不说"你肯定行"，而是说：
"你的档案告诉我：
 [具体知识点]最近两周你出错了[N]次，
 主要集中在[精确子类型]。

 [另一个知识点]上次你出错了，
 但后来做了3道同类题，
 第2道和第3道都对了。"

Step 3：把模糊焦虑变成具体任务
"所以'数学不行'这个说法太宽了——
 你现在真正需要的是：
 搞定[精确子类型]这一个点。

 我们现在做3道，针对这个点。
 做完了，你去考试心里有底了。"

Step 4：执行（出3道递进题）
第1道：你历史上做对过的同类型（建立信心）
第2道：精确的弱项点（直面问题）
第3道：弱项点的变形（确认掌握）
```

## 八、当前结果的内部组合

### 8.1 单一责任主体

`k12-learning` 对当前结果负责。通用错题记录、数学深度诊断、概念重建和递进练习是内部视图，不是独立收件人：

- 通用记录视图提供题目证据、学生尝试、通用维度和订正状态。
- 数学深度诊断视图提供子类型 ID、主次维度、判断线索和深度根因。
- 当前主 playbook 只产出一组修复任务、递进练习和掌握判据。
- 概念错误可在同一结果中增加概念重建；攻克后可增加一道迁移题。

### 8.2 最小输入与输出

当前结果只使用：

- 当前题目、学生原答或步骤；
- 通用四维中的初步判断及其证据；
- 用户当前提供或已授权读取的最多 3 份相关错题摘要。

组合结果只保留题目证据引用、通用维度、数学子类型、判断线索、置信度、修复任务和复测标准。证据不足时写“本次记录，不足以判断长期趋势”，不猜测历史次数。

### 8.3 去重、持久化与自动化 seam

- 同一道题只保留一条通用记录；数学深度字段附在同一结果中，不另建第二条错题。
- 多次独立证据或复测结果支持时，才把弱项状态更新为“观察 / 顽固 / 突破中 / 已攻克”。
- 写入 Learning State 前展示字段、目的、位置和删除方式，并获得用户明确同意。
- `k12-learning` 只生成复测内容、建议时间和掌握判据。用户确认需要真实提醒后，才切换到 `k12-automation`；Automation 通过自己的 interface 获取和保存调度授权。
- 周复盘或阶段报告只读取用户当前提供或已授权的最小摘要，不默认展开完整错题历史。
