# 从旧教育 Wiki 增量迁移

旧结构通常只有 `100-Raw / 200-Wiki / 300-Output`，且 index/log 可能位于 `200-Wiki/00-索引与日志/`。

## 规则

1. 先盘点现有目录、AGENTS、wikilinks、附件路径和本地命名，不按目录名直接移动。
2. 输出映射表并等待确认；默认保留已有路径，先增加 `SCHEMA.md` 和缺失导航。
3. 非 Markdown 附件后续新入库统一放 `999-Assets`；已有附件不批量搬移，除非用户接受断链修复范围。
4. 旧 `index.md`、`log.md` 可继续原位使用；在 SCHEMA 记录位置。只有用户明确选择标准化时才移动到 `200-Wiki/` 根。
5. K12 学习画像、错题历史或家长反馈仍受原授权约束；迁移目录不等于获得读取或写入授权。
6. 每批最多移动一个语义目录，运行 link-integrity loop 后再继续。

## 完成标准

- 四层职责有明确映射；不存在两套 active taxonomy。
- Raw 原文未改写。
- 新写入遵守 SCHEMA。
- 本批没有新增 broken link；遗留歧义有精确清单。
- index 与 log 记录本次迁移，而不是伪装成全新空 Wiki。
