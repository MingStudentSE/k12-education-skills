# ⏰ IM 智能提醒

> 一句话定位：在学生或监护人明确授权后，把复习、行动和回访按合适节奏提醒出来。

## 技术实现边界声明

- LLM 本身不具备自主计时或主动唤醒能力；实际调度依赖宿主平台的定时任务机制与自动化工作流引擎。
- 可由 QClaw 等定制化 OpenClaw 平台实现；消息推送应泛化到已接入的 IM 渠道，不绑定单一软件。
- 未获授权时，不创建定时提醒、不做闲置唤醒、不跨渠道推送。
- 即使已获授权，也只有真实 adapter 返回任务 ID、下一次触发时间和控制入口后，才能报告“已创建”；adapter 缺失或失败时只给可复制计划并明确“未创建提醒”。

## 触发边界

- 触发：用户明确要求设置复习提醒、间隔复测、任务执行提醒、探索任务回访，或明确同意接收某类提醒。
- 不触发：只是问题、要讲解、要计划但未同意提醒；此时只给建议方案，学习任务回到 `k12-learning` 处理。
- 最小输入：提醒内容、目标时间/频率、提醒渠道、是否授权；信息不足时先给补充模板。
- 任何长期记录或跨 module 数据传递都必须逐次说明目的、最小字段、接收方和删除方式，并获得明确同意；不存在由 Learning 画像继承的全局共享开关。

## 流程骨架

1. **判断授权**：确认学生或监护人是否同意开启提醒；未同意时只输出建议方案。
2. **明确提醒对象**：区分复习提醒、行动提醒、回访确认提醒或探索成长提醒。
3. **设定节奏**：复习类可把 Day 1/3/7/14/30 作为无个体证据时的起始模板，再按主动提取表现调整；行动类按计划节点；考前按剩余天数降噪。
4. **确认渠道与控制口令**：告知查看、暂停、恢复、取消、调整频率和撤回数据传递授权的方法。
5. **执行与反馈**：调用真实 adapter 并核验返回结果；根据独立答对、靠提示、答错或无回应调整下一次提醒。无 adapter 或调用失败时改给可复制计划，不声称已创建。
6. **队列化呈现**：当用户问“今天有什么”时，用高优先级/今日到期/本周内输出统一队列。

## 授权与控制规则

- 启用前必须明确提醒类型、频率、大致时间段、渠道和本次必要数据范围。
- 用户可随时说“暂停提醒”“取消这条提醒”“今天不要提醒”“不要把结果交给其他模块”。
- 默认夜间免打扰：22:00-8:00 不发；如需例外必须单独授权。
- 普通日最多 3 条，考前冲刺最多 5 条；压力过高时降频或只保留最高优先级。
- 提醒时间优先使用用户本次明确给出的时段；当前提醒 interface 不读取 Learning profile，也不从画像推断调度授权。

## 提醒策略

- 理解类：用自己的话解释；按标准间隔复测。
- 记忆类：填空/默写；前 3 天可更密集，但必须受数量上限约束。
- 应用类：附一道变形练习；检查能否迁移。
- 错题类：针对同类错误复测；可用 Day 1/2/5/10/21 作为无个体证据时的强化起始模板，再按复测表现调整。
- 行动类：提醒具体可执行动作，而不是空泛目标。
- 回访类：记录完成率、响应率和必要调整建议；只有用户明确指定接收方时才输出本次最小摘要，不自动写入其他 module。

## 失败红线

- 不在未授权时创建提醒、闲置唤醒或跨 IM 推送。
- 不把“几天没对话”当作默认唤醒理由；只有用户订阅的指定提醒才可发送。
- 不默认长期保留所有提醒；必须提供暂停、取消、调频入口。
- 不把提醒结果默认同步给其他 module；每次传递都要重新确认目的与最小字段。
- 不用提醒制造压力、羞辱或连环轰炸；允许跳过、延后、暂停。
- 不把 runtime 写死为某一平台或某一个 IM 软件。
